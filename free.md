# 📊 Показатели памяти в Linux (`free`)

---

### 🔹 `total` (Всего)
Общий объем доступной системе памяти (сумма всей установленной физической памяти за вычетом некоторых резервов ядра).

### 🔹 `used` (Использовано)
Занятая память. В современных версиях Linux (начиная с procps-ng 3.3.12) рассчитывается как `total - available` (в старых версиях считалась по формуле `total - free - buffers - cache`). Это весь совокупный объем RAM, который сейчас чем-то занят и не может быть легко очищен. Сюда входят:
- память самого ядра Linux;
- память всех запущенных программ и сервисов;
- разделяемая память (`shared`).

### 🔹 `free` (Свободно)
Абсолютно неиспользуемая физическая память (простаивает). Это «стерильная» память. В ней вообще ничего нет. Linux держит этот показатель небольшим (обычно несколько сотен мегабайт или единицы гигабайт), потому что отдавать пустую память под кэш диска гораздо выгоднее для производительности.

### 🔹 `shared` (Разделяемая)
Память, используемая совместно разными процессами (например, через `tmpfs`). Это узкоспециализированная память. Она отображает объем RAM, к которому одновременно имеют доступ сразу несколько независимых процессов. Если на сервере есть БД, то `shared` будет также содержать значение `shared_buffers`, так как эту память используют все дочерние процессы `postmaster`. Также в основном этот показатель растет за счет:
- использования временной файловой системы в оперативной памяти (`tmpfs`, например, каталог `/dev/shm`).

### 🔹 `buff/cache` (Буферы и кэш)
Память, которую ядро Linux использует под дисковый кэш и буферы ввода-вывода (ускоряет работу с файлами). Эту память ядро может мгновенно освободить и отдать под запросы приложений, если им не хватает RAM.

## ⚠️ Но ВАЖНО

### 1. Архитектурная хитрость: всё есть файл
В Linux исторически существует механизм `tmpfs` — это виртуальная файловая система, которая живет исключительно в оперативной памяти. Когда вы создаете разделяемую память (Shared Memory) для Postgres, ядро Linux выделяет ее не «в воздухе», а внутри `tmpfs`. Для ядра этот блок памяти выглядит точно так же, как обычный файл, просто созданный в RAM.

### 2. Как Linux работает с файлами (Page Cache)
Когда любое приложение в Linux читает или пишет файл на обычный диск, ядро перехватывает этот запрос и создает в оперативной памяти копию этих данных — Page Cache (кэш страниц). Это делается для того, чтобы при повторном запросе не читать медленный диск.
Поскольку `tmpfs` (где лежит память Postgres) притворяется файловой системой, ядро Linux обрабатывает ее через тот же самый механизм — Page Cache.

### 3. Как утилита `free` собирает статистику
Когда вы запускаете `free`, утилита не опрашивает процессы по отдельности. Она просто открывает системный файл `/proc/meminfo` и смотрит на общие счетчики ядра.

Внутри ядра Linux происходит следующее:
1. Вы выделили 194 ГБ под разделяемую память.
2. Ядро выделило её через механизм страниц виртуальных файлов (`tmpfs`).
3. Ядро прибавило 194 ГБ к глобальному счетчику `Cached` (потому что технически это Page Cache).
4. Утилита `free` берет этот счетчик `Cached`, складывает его со счетчиком `Buffers` и выводит результат в колонку `buff/cache`.

> 💡 Получается, в `buff/cache` входит `shared` + часть памяти, которую можно освободить в моменте (ее получим разницей `buff/cache - shared`). То есть:
> **`available = (buff/cache - shared) + free`**

### 🔹 `available` (Доступно)
Самый важный показатель для администратора. Это примерная оценка объема памяти, который можно выделить для запуска новых приложений прямо сейчас без обращения к Swap (учитывает свободную память плюс часть буферов и кэша, готовую к очистке). Это сумма `free` + часть `buff/cache`, которую ядро может мгновенно и безболезненно забрать у кэша и отдать вашему новому приложению.
